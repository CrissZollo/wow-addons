# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Addons for **World of Warcraft: Forever** (`.toc` `## Interface: 16001`), aimed at non-technical players
on both Windows and Linux (WoW through Wine/Proton). One folder per addon, named exactly like its
`.toc`. Currently the only addon is **Herald**. `updater/` is not an addon: it's the shared Addon Updater
that every download carries.

## Commands

There is no test suite or linter. The checks and workflows are scripts in the repo root:

```sh
./check-wiki.py                    # verify repo/wiki format for every addon (exit 1 lists problems)
Herald/build/package.sh            # build Herald/dist/Herald-Windows.zip + Herald-Linux.zip
./release.sh <Addon> <version> ["what's new"]
                                   # needs a clean tree; bumps .toc, builds, rewrites download links,
                                   # writes updates.json, commits, tags <Addon>-v<version>, pushes,
                                   # gh release, publishes wiki. Players' updaters install it within 30 min
./publish-wiki.sh                  # copy wiki/*.md to the GitHub wiki repo (SSH host alias github-crisszollo)
```

`release.sh` and `publish-wiki.sh` refuse to run until `check-wiki.py` passes. Both push to GitHub, so
don't run them unless asked.

Running the Herald watcher locally (Python 3.8+, stdlib only):

```sh
python3 Herald/watcher/herald.py test --dry-run   # print every sample Discord card as JSON, no posting
python3 Herald/watcher/herald.py --dry-run        # watch the log and print instead of posting
python3 Herald/watcher/herald.py list             # recorded first kills
```

Testing the updater without touching the real PC setup: set `ADDON_UPDATER_HOME` (its state/program dir) and
`ADDON_UPDATER_SOURCE` (e.g. `file:///tmp/src`, containing `main/updates.json` and `<tag>/<repo files>`), pass
`--game <fake _forever_ dir>`, and always `install --no-start`. Without `--no-start` it writes a real systemd
unit / Startup shortcut. A fake running WoW: `bash -c 'exec -a "C:\\x\\Wow.exe" sleep 300' &`.

Config/state live in `~/.config/herald/config.json` and `~/.local/share/herald/` (Linux) or
`%APPDATA%\Herald` (Windows), not in the repo.

## Herald architecture

Herald has two halves, because WoW addons can't reach the network:

1. **In-game addon** (`Herald/Herald.lua`): forces combat logging on, and stores per-character
   snapshots (level, XP, gold, stats, gear) plus milestone level-ups in the `HeraldDB` SavedVariable.
   It also calls `Screenshot()` on milestone levels. WoW only writes SavedVariables at logout or `/reload`,
   so anything that depends on `HeraldDB` posts then.
2. **Watcher** (`Herald/watcher/`, a Python program on the PC) runs one polling loop (`watch()` in
   `herald.py`) that does two things:
   - tails the newest `Logs/WoWCombatLog-*.txt`; `Tracker.handle()` parses combat-log CSV lines and
     posts first-kill / boss-encounter / enemy-player embeds to a Discord webhook (state in `kills.json`).
     A log that already exists at startup is skipped to its end; later logs are read from the start.
   - `progress.Progress.check()` watches `WTF/Account/*/SavedVariables/Herald.lua` mtimes, parses the Lua
     table with its own small parser (`parse_saved_variables`), and posts milestone cards (with the
     screenshot attached) and progress reports (state in `reports.json`).

   The same file also has the setup/install side: finding the game dir (Windows registry/drives, or
   common Wine prefixes on Linux), copying the addon into `Interface/AddOns`, autostart (Windows
   Startup folder, or a systemd user unit generated by `set_autostart_linux()`), and lock/stop files
   for a single background instance. `watcher/herald.service` is a leftover dev unit; the installer
   doesn't use it.

Herald registers itself with the Addon Updater (`register_updater()`), and `watch()` restarts the process
(`restart()`, `os.execv` on Linux) when the updater replaces `herald.py`/`progress.py`, resuming the combat
log where it stopped.

The data contract between the two halves is the `HeraldDB.chars[<Name-Realm>]` shape (`info`, `start`,
`last`, `milestones`, `sessionStart`). Changing a field in `Herald.lua` means updating `progress.py`.

## Addon Updater (`updater/`)

- `updater.py` (stdlib-only, Python 3.8+): `install --addon X [--addon-dir D] [--program-dir D] [--game D]` copies
  itself to a fixed home (`%LOCALAPPDATA%\AddonUpdater` with its own embedded Python, or
  `~/.local/share/addon-updater`), installs the in-game companion, registers the addon in `state.json` and sets
  up autostart (Startup shortcut / `addon-updater` systemd user unit). The background loop reads
  `https://raw.githubusercontent.com/CrissZollo/wow-addons/main/updates.json` every 30 min and downloads changed
  files (by SHA-256) from `<tag>/<path>`. File targets: `addons/<Folder>/…` (only the component's own folder),
  `program/…` (the registered program dir), `updater/…` (its home). It replaces itself and re-execs.
- While WoW runs (process check for `Wow*.exe`), it only installs updates with the same file list and the same
  `.toc` apart from `## Version`; others are deferred until WoW closes. An addon whose AddOns folder was deleted is
  unregistered; with none left, the updater turns autostart off and removes the companion.
- `AddonUpdater/` is the in-game companion: at login it compares each managed addon's `.toc` version with the
  one it saw last time (in `AddonUpdaterDB`) and prints release notes from the generated `Managed.lua`.
  Mid-session notice (experimental, untested in the real client): the program writes a real font or junk to
  `probe/reload.ttf` / `probe/restart.ttf`, and the addon polls `FontString:SetFont()` on them.
- `make-manifest.py` writes `updates.json` (called by `release.sh`); `<Addon>/build/program-files` lists helper
  program files. `bundle.sh` has the shared build helpers (`add_updater`, `add_python`, `zip_dirs`);
  `install-plain.sh` is the Linux installer for plain addons.
- `updater.py` duplicates Herald's game-dir search list; keep the two in step.

Packaging (`Herald/build/package.sh`, helpers in `updater/bundle.sh`): the **Windows** zip bundles a portable
embeddable Python (downloaded once into `~/.cache/wow-addons-build`) and CRLF `.bat` launchers, so users install nothing. The
embeddable Python doesn't put the script's folder on `sys.path`, which is why `herald.py` inserts it
before `import progress`. Keep the watcher **stdlib-only** and Python 3.8-compatible (the Linux
`install.sh` uses the system `python3` and checks for ≥ 3.8).

## Repository format rules (enforced by `check-wiki.py`)

The full checklist is in `templates/README.md`. The main points:

- Every addon needs `<Addon>/<Addon>.toc` with `## Version: x.y.z`, `<Addon>/README.md`,
  `<Addon>/build/package.sh` (plain addons copy `templates/package-plain.sh`; every addon ships
  `<Addon>-Windows.zip` + `<Addon>-Linux.zip` with the updater inside), and a `| **<Addon>** |` row
  in the root `README.md`.
- The wiki in `wiki/` is **bilingual, English and Swedish**, and is the source for the GitHub wiki. Each
  addon gets `wiki/<Addon>.md` and `wiki/<Addon>-på-svenska.md` built from `templates/{en,sv}/wiki-addon-page.md`,
  with **exactly** the fixed `##` sections in order. It also needs a `## <Addon>` section in each shared
  page (install on Windows/Linux, platform differences, troubleshooting) in both languages, a row on
  `Home.md`/`Startsida.md`, and sidebar entries. Snippets: `templates/{en,sv}/wiki-snippets.md`.
- Every wiki page links to its other-language counterpart in its first lines
  (`[[Läs på svenska|…]]` / `[[Read in English|…]]`). When you edit one language, edit the other too. A new
  shared page must be added in both languages, to `_Sidebar.md`, and to `PAIRS` in `check-wiki.py`.
- Download links always use the versioned form
  `https://github.com/CrissZollo/wow-addons/releases/download/<Addon>-v<version>/<file>`. `release.sh`
  rewrites them with sed in `README.md`, `<Addon>/README.md` and `wiki/*.md`.
- The programs' own texts (setup prompts, Discord cards) are English only. The Swedish guides quote
  them and explain them in Swedish.
- Write docs for players, not developers, and always cover both Windows and Linux.
